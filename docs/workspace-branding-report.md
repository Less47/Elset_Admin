ELSET Admin workspace branding - 10 September 2026

1. **Existing sidebar branding.** Before editing, the desktop sidebar used the bundled `/elset-logo.png`, a role-specific Menu heading, and explanatory copy in a large card. Icon-only mode used `/favicon.png`. The mobile drawer separately hardcoded the ELSET image, visible Application navigation title and role menu label. `WorkspaceShell.jsx` and `MobileWorkspaceNavigation.jsx` own these areas; the bottom sign-out area and shared BuildIndicator are separate.

2. **Existing upload/storage architecture.** No configurable workspace logo or reusable logo-upload endpoint existed. Job photos already use image data URLs stored in SQLite attachment values; there was no general managed image-asset uploader with PNG/JPEG/WebP validation. Shared company fields live in the workspace database's `settings` key/value table and use targeted `/api/settings` requests. Personal appearance lives separately in `user_ui_preferences`. Document templates expose company details/text, while PDF generation independently loads `public/elset-logo.png`. That document source remains unchanged. The audited Fly configuration mounts its existing volume at `/app/data`; the production workspace database lives there.

3. **Removed presentation.** Removed the hardcoded sidebar image/favicon, role Menu heading, long paragraph, oversized branded card and visible mobile drawer title/role copy. The drawer keeps a screen-reader-only title/description and its close button. Navigation order, routes, permissions, sign-out and the build indicator are unchanged by this task.

4. **New dimensions.** The desktop logo well is 86px high, with a maximum image size of 150x70px. It uses centered padding, a 1px themed border and a muted semantic surface. At the standard sidebar width, this replaces the roughly 170px previous block. Images retain their aspect ratio through `object-fit: contain`; original image bytes are neither cropped nor recoloured. The Settings preview uses the same component in a 246px-wide well.

5. **Fallback.** Lucide `Building2`, 36x36px normally and 32x32px in icon-only mode. No configured image, an invalid reference or a failed image request produces this icon. The component removes failed images from the DOM, avoiding broken-image placeholders. Uploaded images use `alt="Workspace logo"`.

6. **Settings location.** Settings > Preferences > Workspace Branding, above Company Details. It contains a preview, Upload/Replace Logo, Remove Logo, compact format/size guidance, and inline progress/errors. Removal uses a small confirmation dialog. Successful changes update the current sidebar immediately. As with existing shared Settings endpoints, uploading is available in SQLite mode; legacy JSON mode displays an availability message.

7. **Persistent storage and validation.** One `workspaceLogo` record in the existing SQLite `settings` table contains the original bytes as base64, validated MIME type, dimensions and SHA-256 asset ID. There is no new table/schema migration, external upload directory or Better Auth storage change. Native SQLite backups include the bytes automatically; a test reopens the backup and compares the exact original bytes. Uploads are limited to 2 MiB, 4096px per side and 8 million pixels. PNG, JPEG/JPG and WebP are accepted; SVG is rejected. The server checks magic bytes against the declared MIME type and fully decodes the image before persistence. Added Sharp 0.35.4 for decoding, using its strict failure and pixel-limit options ([official constructor documentation](https://sharp.pixelplumbing.com/api-constructor/)). The original image is stored, preserving transparency and colour. White pixels inside the uploaded ELSET test logo remain part of that image; the surrounding well is themed.

8. **Shared setting and targeted API.** The shared state loader projects the asset to `settings.workspaceLogoUrl`, without sending its base64 contents with every workspace response. Upload uses authenticated `PUT /api/settings/workspace-logo` with bounded image bytes; removal uses `DELETE` on the same endpoint. Image reads use `GET /api/settings/workspace-logo/<sha256>`. Replacing an image changes that URL, and responses use `private, no-store`, preventing stale replacement images. Generic Settings writes cannot bypass validation by assigning `workspaceLogo` or `workspaceLogoUrl`. Frontend success applies only the returned logo reference; no whole-workspace save is sent. Personal theme presets and Reset UI retain their existing, separate preference keys. Other sessions receive the shared logo when loading/refreshing workspace state; no live push mechanism was added.

9. **Permissions.** Reused the existing authenticated session and `requireRole(["admin", "office"])` Settings policy for upload, replacement and removal. Authenticated technicians may read the logo but cannot change it. Anonymous reads/writes are rejected. Tests exercise the real application sessions as well as the route boundary. No role or authentication implementation changed.

10. **Mobile behavior.** The drawer uses the same logo component with a 64px well and a maximum image size of 150x48px. Header padding respects safe-area insets; navigation starts directly below it. Its close control, accessible dialog name, keyboard focus restoration, scrollable navigation, sign-out and build footer remain functional. The mobile workspace toolbar outside the drawer retains its existing page/role context.

11. **Icon-only behavior.** A 48x48px logo well fits the existing configured sidebar width. The uploaded image is contained within 38x38px; a fallback icon appears if needed. No sidebar width setting or navigation layout was changed.
