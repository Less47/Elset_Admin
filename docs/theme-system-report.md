ELSET Admin theme system overhaul - 10 September 2026

1. **Existing architecture.** React/Vite with Tailwind v4, semantic shadcn/Radix primitives, shared database/workspace CSS, and page-specific Calendar/Maintenance/document styles. UI Settings used eleven saved colour seeds plus two layout preferences. The account preference store and its debounced queue persist narrow PATCH requests to /api/user-preferences; company preferences have a separate /api/settings path. useThemePalette previously updated only actions, borders, shell, dialogs, and database accents. Standard card, foreground, muted, input and popover tokens remained at their light defaults, and the .dark class was never activated by Midnight.

2. **Hardcoded light surfaces found.** The initial search found 1,125 matches across 868 lines in 51 files. buildDataViewTheme mixed its seed 72-88% toward white; the page gradient also inserted a 50% white midpoint. index.css mixed workspace containers and toolbars with white and fixed toolbar text to #0F172A. Calendar.css fixed the main calendar, mini navigator, inspector and drag preview to white. Maintenance.css fixed cards to #FFF, metrics to #F8FAFC and metadata to slate. DocumentWorkspace.css used #FFFFFFEB editor sections. JSX used bg-white and text-slate-* throughout customer/site/job/document workspaces, database views, mobile record cards, Settings, Service Board, shared forms, autocomplete and sheets. Leaflet popup text/buttons used inline fixed colours. The original search evidence is in test-results/theme/theme-colour-audit.txt and theme-inline-audit.txt.

3. **Semantic tokens.** The new pure theme-tokens.js builder drives existing --background/--foreground, --card/--card-foreground, --muted/--muted-foreground, --secondary, --accent, --popover, --primary, --border, --input (border), --ring, --sidebar-*, --workspace-hero-*, --dialog-*, and --data-view-* tokens. Added roles are --surface-raised, --surface-hover, --surface-selected, --input-surface, --text-secondary, --border-strong, --primary-hover, --link, --page-gradient and --scrim. Status foreground/surface/border/hover families retain info, success, warning, danger, maintenance and special meanings. Dialog-local tokens support a custom popup colour independently of the main application. Tokens are installed on documentElement so Radix portals and detached map/drag elements inherit the same palette. The hook also sets .dark and the native colour scheme.

4. **Exact Midnight strategy.** Page #080D16 to #0A101B; primary surface and database rows #101826; raised cards and popup base #162235; muted surfaces/table headers #1B293D; inputs #0C1421; hover #253851; selection #233D5A; thin borders #34465E. Text is #F5F7FA, secondary #CBD5E1, metadata #A6B5C9. Sidebar #111827, sidebar header #132A43, active navigation #1B436F, main header #111827, action #1469B8. Strong borders and popup input/footer depth derive from these seeds. Changing the database accent still updates Midnight header/hover/selection colours. No inversion or image filters are used.

5. **Database views.** Existing data-card, data-grid, data-grid-header, data-grid-row, data-stat-card and data-record-card rules now resolve to the coordinated palette. Headers, rows, alternate rows, hover and grid lines have distinct semantic roles. Customers, Sites, Job History, Invoices, Staff and Inventory use these same roles on desktop and mobile. Maintenance uses its shared semantic card/metric rules. Explicit cell/metadata utilities now request foreground or secondary/muted text.

6. **Forms, dialogs and sheets.** Shared Input, Textarea, Select, Button, Tabs and Dialog primitives use semantic surfaces and foregrounds. Native selects, placeholders, caret, selection, read-only/disabled states and autofill styling are covered. Focus rings and hover/selected states remain visible. Autocomplete and searchable customer pickers use popup colours. Radix dialogs and mobile drawers/sheets inherit document tokens, with a local popup foreground/surface scope for custom colours. Dialog body, header, footer, inner cards and fields theme together. Save-error and validation styles use semantic danger colours.

7. **Calendar.** The main surface, weekday strip, date cells, out-of-month cells, mini navigator, Job Queue, desktop Day Inspector, mobile day sheet and drag preview all theme. Grid lines remain visible; today and selected dates keep separate indicators. Maintenance chips retain a teal family, separate from normal job status chips. Scheduling and drag/drop logic are unchanged.

8. **Service Board.** To Do, In Progress and Completed keep amber, blue and green meanings, using dark tinted columns/cards and readable badges in Midnight. Value bubbles, tags, filters, sort controls, Tomorrow panel and mobile board sheets use semantic surfaces. Solid small business indicator dots remain intentionally coloured.

9. **Light presets.** Classic uses ice/blue surfaces (#EAF7FB seed) with blue/orange branding. Copper uses parchment/cream (#F1DECD) with copper/brown framing. Evergreen uses sage/eucalyptus (#DFEADA) with forest framing. Rose uses restrained blush (#EFDBE3) and plum/wine. Desert uses sand/ochre (#EEE1C3) and amber/charcoal. Every preset supplies all eleven persisted seeds; all derive distinct raised, muted, input, table and popup treatments. UI Settings previews use the same builder as the application. Preset cards include miniature surface layouts, dots and a selected state.

10. **Contrast/readability.** Replaced the weighted brightness threshold with WCAG relative luminance and contrast comparison. Presets have explicit text palettes; derived metadata, links, header/sidebar text and custom foregrounds receive contrast checks. Tests target at least 4.5:1 for body/metadata across normal, raised, muted, input, hover, selected and table surfaces, and for buttons, navigation, headers and business badge pairs. Midnight's dimmest tested body/metadata pair exceeds 5.7:1. Custom foreground selection is checked across 4,096 RGB colours. Status meaning, thin borders, responsive layout and image artwork are preserved.

11. **Backward compatibility.** The stored schema is unchanged: eleven colour seeds and the existing layout/display fields. Database surface now coordinates the application surface family, so no new colour controls or migration columns are needed. Old/partial/invalid preferences retain normal fallbacks. The old Midnight seed signature upgrades on read to dark surface/popup/page values; unrelated custom actions, borders and layout are retained. Existing records are not rewritten or deleted. The upgrade is idempotent.

12. **Per-user persistence.** The existing authenticated preference endpoint, account-keyed store, debounce/coalescing queue, retry behavior and sign-out isolation remain in place. Reset UI sends only the current account's UI keys. Tests use simultaneous admin/office/technician sessions and verify isolation, refresh, a fresh browser and server restart. Workspace business records are compared after every browser test.

13. **Rapid switching.** A 20-preset browser burst ends on Midnight and produces one narrow account PATCH; the second account stays Classic. Refresh and resetting the second account preserve the first account's Midnight palette. Existing delayed-acknowledgement, rapid colour entry, failure/retry, pending-navigation, latest-selection and health checks are also retained.
